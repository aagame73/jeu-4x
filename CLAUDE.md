# Projet : jeu 4X spatial (titre à définir)

Jeu de stratégie spatiale 4X ORIGINAL sur navigateur, inspiré de l'esprit d'Ascendancy (1995).
Ce n'est ni un remake ni un clone : l'univers, les espèces, les noms, les mécaniques et l'interface sont propres au jeu.

- Solo contre l'ordinateur
- Parties longues : 5 à 10 heures maximum
- Carte de la galaxie en 3D
- Ce que le joueur aime : construire, chercher des ressources, découvrir des systèmes stellaires

Document de concept (Claude Docs) : https://claude.ai/artifact/DmjNSzpHizS7BF9cqtibBg

Décidé le 2026-10-28 : surface des planètes en hexagones ; gisements à épuisement partiel (baisse lente jusqu'à un plancher) ; titre choisi plus tard (nom de code en attendant). Rythme : temps réel avec pause (temps en jours, vitesses x1/x2/x4), et non plus tour par tour.
Début de partie (2026-10-29) : l'Arche (vaisseau colonie aux moteurs de saut cassés) arrive dans un système ; on l'analyse, on choisit la planète et la case de la colonie ; puis spatioport → sondes (qui s'usent) → dock spatial (vaisseaux colonie, améliorations) → défenses.
En développement, `window.jeu` (game, actions, refresh, tick) permet de piloter la partie depuis la console pour tester.
Prototype (2026-10-28) : galaxie 3D + exploration par sondes, en Vite + Three.js (`npm install` puis `npm run dev`, http://localhost:5173, `?graine=42` pour rejouer un amas). Code dans `src/` : `galaxy.js` (génération), `game.js` (règles, tours), `scene.js` (rendu 3D), `ui.js` (interface), `skybox.js` (fond Voie lactée), `ships.js` (vaisseaux procéduraux uniques, un par sonde), `surface.js` (plateau d'hexagones des planètes), `economy.js` (bâtiments, production, chantiers), `systemView.js` (vue 3D du système : étoile, planètes et lunes en orbite ; double-clic sur une étoile ou bouton « Voir le système »), `planetView.js` (vue 3D de la surface), `surfaceFx.js` (animations : eau, volcans, arbres…), `icons.js` (pictogrammes SVG), `research.js` (arbre de 46 technologies, 7 branches, 4 paliers ; débloque bâtiments, vaisseaux, niveaux 2 à 4 des bâtiments et améliorations ; vaisseaux de 4 tailles avec attaque/défense, défense des colonies) + `researchView.js` (écran de recherche, touche R), `save.js` + `menu.js` (sauvegarde : auto tous les 5 jours + 3 emplacements dans le navigateur, export/import de fichier, écran d'accueil), styles : `style.css` + `styles/bandeau.css` (bandeau « Hologramme », polices Orbitron + Exo 2) + `styles/planete.css` (horizon planétaire, panneau de colonie), réglages dans `config.js` (dont `SPECIES`, les 8 espèces jouables). Espèces : `species.js` (espèce de la partie, bonus), `speciesView.js` (écran de choix après « Nouvelle partie », `?espece=vaskhar` le saute, avec `?rivaux=6` en plus pour fixer le nombre d'adversaires, de 3 à 7), `aliens.js` (portraits animés en Canvas), `advisor.js` (conseiller de l'espèce qui lit les nouvelles du journal, en bas à gauche), styles `styles/especes.css` ; plan dans `docs/plan-especes.md`. Rivaux : `empires.js` (empires simulés, expansion, colonies cachées ; réglages `RIVAL_AI` dans `config.js`), `contactView.js` (cinématique plein écran du premier contact), plan dans `docs/plan-rivaux-ia.md`. Diplomatie : `diplomacy.js` (notes, échanges, traités, convois, propositions ; réglages `DIPLOMACY` dans `config.js`), `diplomacyView.js` (écran, touche D), `dialogues.js` (répliques par espèce ; `node docs/outils/liste-dialogues.mjs .` les liste dans `docs/dialogues-especes.md`), plan dans `docs/plan-diplomatie.md`. Publication : GitHub Pages par GitHub Actions (`.github/workflows/deploy.yml`), à chaque push sur `main` ; dépôt public, donc aucune donnée personnelle (commits signés aagame).

L'utilisateur parle français. Il a eu du mal à lire les longues réponses dans le terminal (le défilement ne marchait pas) : faire des réponses courtes et mettre le contenu long dans le document.
